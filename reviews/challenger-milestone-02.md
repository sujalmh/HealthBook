## Assumption Violations
**`src/components/vault/DocumentDropzone.tsx:14-18`**: assumes any text `includes('%PDF')` is garbled binary → false-positive for clinical notes literally containing "%PDF" (e.g., "Apixaban note: %PDF"). Demonstrated Case 1. Fix: check `startsWith('%PDF-')` at 0-5 and ratio >0.3, not substring anywhere; or only treat as garbled if `trim().startsWith('%PDF')` AND binary ratio >0.15.

**`src/components/vault/DocumentDropzone.tsx:98`**: assumes `imageDataUrl.length > 5000` implies image → any 6k clinical note would be misclassified as imageBlob. Demonstrated Case 8 (6000-char `A` string considered image by Dropzone but rejected by `isImageDataUrl`). Fix: remove length>5000 disjunct, only `startsWith('data:image')`.

**`src/core/ai/config.ts:128`**: assumes `overrides['VITE_AI_ENABLED'] === 'false'` string check suffices → boolean `false` from blob `{"VITE_AI_ENABLED":false}` would bypass `bareOnlyFalse` detection (hasBlob true already but still demonstrates type assumption). Demonstrated Case 12. Fix: use `String(overrides[k]).toLowerCase()==='false'` for detection if needed, but better remove bareOnlyFalse logic entirely per above.

**`src/tools/vaultTools.ts:121-131`**: assumes heuristic synthesis from `documentId` (e.g., `"a"` or `"doc_123"` or `"test.pdf"`) is acceptable fallback to ensure ≥1 fact → overflow: any nonsense documentId yields a medication fact (demonstrated Case 7 `doc_123` and `a` both yield 1). This ensures test `test.pdf` not 0 but also synthesizes facts from non-content. Fix: only fallback to `file.name` when `rawText` empty AND `file.name` matches clinical pattern or contains known tokens; otherwise return `[]` or single `clinical note` placeholder with low confidence and flag `synthesizedFromFileName:true`.

**`src/tools/vaultTools.ts:76` + `src/core/ai/config.ts:315`**: assumes `getAIConfigSource()` overrides safe to log → leaks apiKey. Already break but also assumption violation: logging overrides for debug is safe. Fix redaction.

**`src/core/ai/fallback.ts:75`**: assumes `/(?<!\d)\.(?!\d)/` lookbehind supported everywhere — modern browsers/Node 18+ ok but older Safari maybe not; but test shows decimal preservation PASS, so low risk. Keep but note coverage gap: no test for very long 10k payload memory.
