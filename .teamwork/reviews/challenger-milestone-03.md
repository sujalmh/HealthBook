## Assumption Violations
**`src/tools/vaultTools.ts:87-99` bbox pixel vs normalized assumption** — `extract_fact` creates normalized `x 0.08 width 0.78` for real `rawText` lines but synthetic empty/whitespace branch uses pixel `x 100 y 100 width 200 height 30`. `src/core/vault/LocalVault.ts:218-219` validator allows `0-1000` so both pass, but `BoundingBoxViewer` expects 0-1 normalized (renders highlight at 100*100% off-canvas). Reproduced `/tmp/challenger-m3-adversarial.ts:165` `empty bbox x=100`.

**`src/components/vault/DocumentDropzone.tsx:96-97` PDF readAsText assumption** — assumes PDF can be read as text via `FileReader.readAsText`. Real PDFs are binary; `readAsText` produces garbled `rawText` (mojibake, null bytes). `vaultTools` still slices 160 chars and creates facts, so no crash but poor extraction. Should use `readAsArrayBuffer` + PDF.js. Flagged `/tmp/challenger-m3-adversarial.ts:343`.

**`src/fixtures/patient_profiles.ts:35` + `src/fixtures/index.ts:13-17` src->test bridge assumption** — assumes importing from `../../test/fixtures/legacyMocks.ts` is test-only and tree-shaken away. `grep mockShanti src 0` passes, but source still depends on test. In production `dist` it is tree-shaken (verified `grep Shanti dist 0`), so not bundled, but violates layering and could reintroduce mock data if any `src` file imports `patient_profiles` re-exported symbols. Present as warning.

**`src/tools/vaultTools.ts:87` empty rawText synthetic fact assumption** — assumes `rawText.trim().slice(0,160)` empty should still create 1 fact for `patientId` with generic `dose 10mg`. This creates synthetic medication not from user file, misleading for empty uploads (e.g., user drops empty PDF). Should instead return validation error or 0 facts.

**`src/components/homelab/UploadLabModal.tsx:42-46,57` hardcoded lab defaults assumption** — assumes `editForm` defaults `1.90/28/4.8` are valid placeholders for empty vault. If user clicks `Approve & Add to LabStory` without editing, synthetic labs `1.90/28` leak into real vault even though `upload_lab_image` tool now parses real `imageBlob`. Modal still uses `mock_photo_slip_blob_base64` string (line 57) instead of real file input.

**`src/core/vault/LocalVault.ts:212-219` bbox validator 0-1000 assumption** — assumes `0-1000` range covers both normalized and pixel, but UI expects normalized only. Allows pixel 100 to pass validation but renders incorrectly. Should enforce 0-1 for normalized or validate pageIndex 0.
