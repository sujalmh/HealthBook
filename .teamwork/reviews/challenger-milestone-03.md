## Assumption Violations
**`src/core/vault/LocalVault.ts:643-649` `isSeeded` conjunction `hasMeds && hasLabs`** — `src/core/vault/seed.ts:151` delegates to it; partial state (1 med 0 labs) returns `false` causing wasteful full baseline reinsert. Reproduced `6a-6c` `med_partial_001` → `isSeeded false` → `inserted.labs 35 meds 5`. Per-record `has(id)` prevents dup so not crash, but violates strict idempotency expectation and wastes 35 inserts. **`src/core/vault/supabaseSync.ts:213-228` `HYDRATION_MAPPINGS` duplicate `meds`+`medications` → double-count** — both map to `vault.meds` same `Map`; hydrate of 1 remote med counts as 2 hydrated (log `4a hydrated 2`, `7a hydrated 2`, `13a 10000`). Counts in `HydrationResult.counts` split per table, inflating `hydrated` total and logs. Not crash but misleading telemetry. Hardening: dedupe or alias only one, or sum unique ids.

**`src/core/vault/supabaseSync.ts:257-303` per-table error returns `{hydrated:0,skipped:false}` vs `postgresql://` skipped `{skipped:true}` semantics split** — `fetch throw` case (11a) returns `hydrated 0 skipped false` while Postgres no-REST returns `skipped true`; both fallback to seed, but `skipped` meaning is ambiguous (all-tables skipped vs per-table errors). Bootstrap `src/main.tsx:44` logs `result.skipped` only, so fetch-error path loses `error` visibility. Not crash, but log confusion. Hardening: propagate `error` field or unify `skipped` only when all tables skipped.
