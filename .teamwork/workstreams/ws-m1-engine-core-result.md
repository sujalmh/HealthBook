## Learnings
- Polyfill must be Promise-exact and share specRegistry with engine to avoid duplication; direct sync handling in engine for jsdom fallback simplifies immediate visibility for `getRegisteredTools` sync callers (tests use forEach without await) while still providing Promise shim for `document.modelContext`. Splitting native vs polyfill branches avoids double dispatch.
- AbortController dedup requires storing controller per tool and aborting before re-register, plus signal abort listener that deletes both registries and fires toolchange — ensures HMR duplicate InvalidStateError graceful skip.
- PatientId bridging at call time via localStorage read (not cached at register time) prevents orphan '' and hard-coded patient-s-devi; must be done in execute wrapper via `derivePatientContext` not via caller-supplied context.
- InputSchema stringification must handle both object and pre-stringified JSON, and TypeError on circular — serializeInputSchema helper centralizes.
- Toolchange EventTarget shim via `new EventTarget()` works in jsdom but fallback map needed for environments without; ontoolchange property needed for spec §4.4.
