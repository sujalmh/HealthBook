## Learnings
- Cold start gate must early-return before vault grid rendering to avoid flash of Shanti or empty vault with wrong patientId. Using `isHydrated` loading state prevents hydration mismatch (localStorage parse async) and ensures gate shows centered card on first paint, not vault. Pattern: `useEffect` restore → `isHydrated` guard → `if (!activeProfile) return gate` → else shell.
- `WebMCPEngine.defaultContext` must not be static constant; must derive from `localStorage` at execution time (not constructor) to reflect newly created account without reload. Captured storedProfile inside `execute` via closure ensures dynamic resolution per call; spreading `...context` then overriding with resolved ensures explicit caller params still win but fallback to stored session.
- `App.tsx` proxy switcher genericization: keeping `patientId` same as real userId while toggling `isProxy`/`onBehalfOf` preserves vault isolation (all vault queries use `activeProfile.userId` which remains real userId, not `patient-child-003`). Child proxy previously used separate patientId (`patient-child-003`) which would switch vault context to different patient — incorrect for Create Account gate where all 8 modules work on that `userId`. Now child proxy keeps same `userId` but `onBehalfOf` child name, maintaining per-account scoping.
- Component default prop hardcodes (`patientId='patient-s-devi'`) leak into grep even when App passes real prop, because grep scans source literals. Must replace defaults with `''` + fallback to `localStorage` or empty to achieve grep 0. Blanket `sed` across `src/components` is safe if App always supplies prop; fallback empty yields empty vault (0 facts) which matches empty-state verification ("No records here yet" 134-148) until upload.
- `fhirExporter.ts` fallback `patientId || 'patient-s-devi'` is a hidden hardcode outside App/components grep but still represents mock fallback for FHIR bundle generation. Changed to `''` and generic `Patient` name to ensure per-account isolation; downstream dossier will pass real `patientId` from stored profile, so empty fallback not used after login.
- Screenshot discipline: puppeteer-core with `executablePath /Applications/Google Chrome.app` is more reliable than `browser.open` for localStorage manipulation (requires `page.evaluate` to clear/set). Capturing 6 viewports (320/375/768/1024/1280/1440) for both gate and vault ensures no pill gaps and `max-w-md` centering verification per TEST_INFRA.md 6 viewports requirement. All JPEGs valid JFIF >5K, gate shows centered card `max-w-md mx-auto` with 44px controls, vault shows empty states clean.
- Preserving invariants: tokens (`bg-canvas-bg #F3F4F6`, `primary #4F46E5 light #EEF2FF`), direct voice (`Drop a PDF or photo to extract details`, `Add Your Health Papers`), `EventBus` relevance matrix, 40 tools, hidden wrappers 8, `isSupabaseEnabled` and `wireLocalVaultToEventBus` in `main.tsx` remain intact; `drug_knowledge` not touched.
